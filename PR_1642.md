## Summary

Implemented an ERC-4626 style auto-compounding vault in `contracts/yield/src/lib.rs` on top of the existing yield-distribution contract.

**Vault API**

- `configure_vault(admin, asset, yield_source, revenue_distributor, performance_fee_bps, caller_bounty_bps)` — one-time setup (2% / 0.5% by default in tests), `update_vault_fees(admin, ...)` for admin changes.
- `deposit` / `mint` / `withdraw` / `redeem` — ERC-4626 style share accounting with round-down for deposits/redemptions and round-up for withdrawals/mints to protect remaining holders.
- `total_assets`, `total_supply`, `balance_of`, `convert_to_shares`, `convert_to_assets`, `preview_*`, `share_price`, `pending_yield` — views.
- `harvest(caller)` — permissionless: optionally pulls accrued yield from a configured `yield_source` (`collect_yield(recipient)`), derives the real yield from the vault asset balance delta, pays the performance fee to the revenue distributor and the caller bounty, then reinvests the remainder into principal. Share supply is unchanged, so the share price grows monotonically.

**Safety**

- Checks-effects-interactions: storage is updated before external token transfers.
- Fees are validated (`<= 10_000 bps`, sum `<= 100%`), checked arithmetic is used throughout, and all vault operations honour the existing security-registry pause hook.
- A malicious yield source cannot over-credit yield: the amount is derived from the actual token balance, not the source's return value.

**Acceptance criteria**

- Harvest compounds yield into principal (`total_assets` grows, share supply unchanged).
- Caller bounty rewards external automation bots (permissionless `harvest`, bounty paid to caller).
- Share price increases monotonically over compounding cycles (4-cycle test with strict growth).
- Deposit / harvest / withdrawal round-trip, late-depositor share pricing, fee math and error cases are covered.
